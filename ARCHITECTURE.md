# Architecture

Two public parts: the linter (`arkui-sem/`) and the demo project where agents use it (`sandbox/demo/`). The bench that
measures the linter on masked real code is the private submodule `bench/` (its `README.md` has its layout). Docs are
in `docs/` (map: `AGENTS.md`).

## How the linter works

```
.ets edit ──► fact extractor ──► rule candidates ──► slice + question ──► System One judge ──► p
 (agent tool)    (src/ets/)        R1 / R2-d / R3 / R4     (judge.ts)          (Jev, Clef, ...)      │
                                                                                                    ▼
                         agent feedback ◄── findings (p ≥ 0.8) / questions (0.5 ≤ p < 0.8)  (engine.ts)
```

The opencode plugin runs this after each edit tool call, gates the session once on idle while findings remain, and
gives the agent the `arkui_check` tool.

## Layout

```
README.md, AGENTS.md, CLAUDE.md (@AGENTS.md), CONTRIBUTING.md, ARCHITECTURE.md
.gitignore, .gitattributes                LF line endings everywhere; ignores refs/, sandbox scratch, the local setup notes
docs/                                    see AGENTS.md for the map
docs/demo/rules.html                     one static page that animates each rule's recorded demo session (edit, breakage, judge, report, fix)
docs/demo/rules.zh.html                  the same page in Simplified Chinese (session text stays in English, as recorded)
scripts/setup.mjs [--doctor]             build the linter, install the plugin into sandbox/demo, enable .githooks; runs bench/setup.mjs when present
.githooks/pre-commit                     Biome check of staged arkui-sem/ files, typecheck when TypeScript is staged
.github/workflows/test.yml               CI: npm ci + npm run lint + npm test in arkui-sem/ on Linux and Windows (ripgrep installed for the call-site search), every PR and push to main
.github/pull_request_template.md         PR description: what and why, how it was checked, notes
.claude/settings.json, opencode.json,    deny rules for the key file and `arkui-sem config`
.codex/rules/arkui-sem.rules               (Codex: exact command prefixes; test with `codex execpolicy check`)
.gitmodules                              bench → ../arkui-sem-bench.git (private; relative to this repo's URL)
bench/                                   private submodule: datasets, runs, results, eval scripts, evaluation docs
refs/arkeval/                            ArkEval v1/v2 paper text (pdftotext; git-ignored)
sandbox/demo/                            the demo project (opencode): R1 pages in entry/src/main/ets/pages/ (Profile: nested write,
                                           Counter, Feed, Toast: undecorated mutated field; Volume: R2 event unwired; Clock: R3; Notes: R4) + DEMO.md; .opencode/ is generated by setup
sandbox/*                                everything else is local scratch (ignored), e.g. a DevEco Code copy of the demo
arkui-sem/                               the linter (opencode plugin, package arkui-sem 0.2.0, ESM, TypeScript)
  README.md, AGENTS.md
  src/opencode.ts      plugin: tool.execute.after feedback, session.idle gate, tool arkui_check
  src/facts.ts         the fact model: what the extractor records per file, and the cross-file lookup interfaces
  src/queries.ts       queries derived from the facts: paths, rendering reads, declared types, class hierarchies
  src/files.ts         .ets discovery under a path; the files an agent's edit touched
  src/rules/           one module per rule on one file's facts: R1.ts (undecorated-mutated-rendered, nested-write-unobserved,
                       depth-aware, V2 gaps; foreach-key-stale, foreach-index-key, lazyforeach-source-rebuilt), R2.ts (event-unwired, given call sites by the engine), R3.ts (unreleased-resource),
                       R4.ts (input-unbound, input-never-read: text inputs wired one way; selection-never-written);
                       candidate.ts (candidate, kinds, fingerprint), index.ts (candidates())
  src/ets/parse.ts     ArkTS parser: ohos-typescript with the SDK ets-loader options (bundled copy: src/ets/options.json,
                       regenerated by scripts/ets-options.mjs)
  src/ets/extract.ts   fact extractor on the syntax tree (single file, no type checker): file visit, imports, types
  src/ets/component.ts a component: fields, one walk per method for reads, writes and their context, reachability,
                       the methods that draw the UI (build(), @Builders and the helpers they call)
  src/ets/callbacks.ts when a function in a method runs: deferred, on an event (a handler), or while drawing;
                       where an access sits (climb: handler, loop, attribute)
  src/ets/loops.ts     loop facts (ForEach/LazyForEach: source, key, what the row does with the item, the components it
                       creates) and builder facts (what each @Builder parameter is read for, passed to a builder or to a child)
  src/ets/rebuilt.ts   rebuilt elements on writes: the new objects a write puts where a field's elements were (map, a loop
                       that pushes, a copy written at an index, an index write, splice), with the properties each keeps
  src/ets/resources.ts R3 facts: listeners, subscriptions, timers and their release
  src/ets/inputs.ts    input facts (TextInput/TextArea/Search: what the text option binds, the fields its onChange
                       stores the typed text in, whether it does anything else)
  src/ets/uses.ts      where a file instantiates components: parent, method, arguments and how each is written
  src/ets/types.ts     type annotations → TypeRef, object literals, per-type records (classes, interfaces, aliases)
  src/ets/syntax.ts, scan.ts, modules.ts, directives.ts, lifecycle.ts   node helpers, file context, imports/exports,
                       disable comments, lifecycle hook names
  src/sdk.ts           DevEco Studio and HarmonyOS SDK lookup (parser options)
  src/project.ts       project index for the rules: imported name → declaring file (relative imports, packages from
                       oh-package.json5 local dependencies and build-profile.json5 modules, Index.ets re-exports), caches;
                       call-site edges: a project scan resolving each file's component uses (callSites), or for one
                       struct a text search and a parse of the matching files only (searchCallSites)
  src/search.ts        text search over a project's .ets files: ripgrep (ARKUI_SEM_RG, PATH, or opencode's own binary), else Node
  src/judge.ts         System One interface, Jev, Clef, answer helpers, questions (Q_R1/Q_R2/Q_R3), slices (SPEC_CARDS),
                       heuristic, DeepSeek (flash, structured output), backend registry
  src/engine.ts        candidates → slices → judge → finding/question bands (thresholds 0.8 / 0.5); agent formatting;
                       KINDS: one entry per candidate kind (judge or facts-only, evidence and fix, disable-comment hint)
  src/config.ts        defaults < ~/.config/arkui-sem/config.json < .opencode/arkui-sem.json < env < plugin options
  src/cli.ts           arkui-sem check | config  (default backend: clef)
  test/                node:test, run from src/ via tsx (npm test, offline): rules/R<n>.test.ts, one file
                       per module (config, engine, deepseek, openrouter, opencode, project, callsites, search, loops, inputs), helpers.ts; test/fixtures/:
                       Counter, Feed, Profile (R1), Ticker (R3), project/
                       (two-module DevEco project: entry imports common by package name)
  scripts/install.mjs
  scripts/compare-callsites.mjs   searched call sites against the whole-project scan on a project or a generated one, with timings
  backends `or-clef` / `or-clef-flash`: Clef via OpenRouter Decisions API (POST https://openrouter.ai/api/alpha/decisions; OPENROUTER_API_KEY or openrouter.apiKey; openrouter.baseUrl)
  backend `laya`: local TypeSafe-compatible server (default http://127.0.0.1:8080; laya.baseUrl / LAYA_BASE_URL);
    state limit ~424 tokens, so slices are trimmed on 422; zero-shot it scores the fixture bugs 0.13–0.27 (unusable before fine-tuning)
```
